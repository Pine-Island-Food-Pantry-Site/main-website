Other editors can work in the same Studio. Coordinate changes to shared content such as Home and Settings, and agree on who will publish an update.

## Work with another editor

Check any presence indicators before editing. If a colleague is already updating the same announcement, coordinate the work so you do not overwrite one another's wording. Shared edits can appear in real time; they do not become public until the relevant document is published.

If **Comments** are available, use the field's comment control to leave feedback or mention a colleague, then resolve the comment when the change is complete. If **Tasks** are available, use the task controls to assign work and track completion. A comment or completed task does not itself publish the document.

## Review and restore a revision

1. Open the document you want to review.
2. Open the document history or changes view using the status/history controls offered by your Studio.
3. Choose an available earlier revision and review the changes, their author, and time where shown.
4. If the history view offers a restore action and your role permits it, restore the intended revision. Confirm what the dialog says will change.
5. Review the restored content as a draft and publish it if you intend to replace the public version.

History availability and retention depend on the project's subscription. Do not assume that all earlier revisions will remain available indefinitely or that a deleted document can be recovered through this view. If the revision or restore control is missing, ask the project administrator for help.

## Account access and permissions

Signing in and editing content are separate from managing the Sanity project. User invitations, roles, and subscription settings are managed by an authorised project administrator through Sanity's project-management tools, rather than the website's Settings document.

If you can read content but cannot edit, publish, or delete it, confirm you are using the invited account and ask the project administrator to check your role. Do not share a colleague's login to bypass an access problem.

## Optional account features

- **Scheduled drafts:** if enabled, use the scheduling action for the intended document, confirm its timezone and scheduled time, and verify its status. Changing **Publish Date** is a separate action and does not create a schedule.
- **Content Releases:** if offered, these can group changes to multiple documents for a coordinated publish. Creating a release or adding a version does not publish it. Have the administrator show you the project's workflow before using it for a live update.
- **Comments and Tasks:** availability and controls vary with project configuration and permissions. Use them for coordination when they are present.

These features are not guaranteed for every account in this Studio. For detailed instructions on controls you have access to, see Sanity's [user guides](https://www.sanity.io/docs/user-guides), including [history](https://www.sanity.io/docs/user-guides/history-experience). Your project administrator can confirm what is enabled.

## Verify and get help

For a restored announcement, compare its public title, overview, body, and image after publishing. For missing access or history, include the document title and the action you need when requesting help. See [support](troubleshooting.md#ask-for-help).
