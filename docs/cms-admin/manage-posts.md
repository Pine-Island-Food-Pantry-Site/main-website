Editing an existing post creates draft changes. Readers continue seeing the previous published version until you publish the update.

## Find and update a post

1. Open **Post** in the content tool. Use Studio search or the document list to find the title.
2. Open the document and edit the relevant fields. For a corrected drop-off time, edit **Post Description** and also **Overview** if the old time appears there.
3. Keep the **Slug** unchanged unless you intend to change the address. Old bookmarks and links can stop working after a slug change; ask the developer to arrange a redirect if needed.
4. Check **Publish Date**. Changing it can move this post in the listing and change the homepage's latest update.
5. Wait for saving, review, and publish. Check the listing, individual page, and homepage when applicable.

## Ordering and website search

The website lists published posts by **Publish Date**, newest first, with six posts per listing page. If dates are identical or missing, do not rely on a particular order. Use distinct, intentional dates for important updates.

The website's search matches **Title** and **Overview**, without regard to capitalisation. It does not currently search tags or the full story. Studio's own document search is a separate tool for finding content to edit.

## Reuse an existing post

If **Duplicate** is available in a post's document actions, use it as a starting point. Change the title, generate a unique slug, check the photo, update the date, and remove old event details before publishing. **Home** and **Settings** are shared documents and cannot be duplicated through the normal document action.

## Unpublish or delete

- **Unpublish** removes the public version while keeping content available as a draft. Links to that post can return a page-not-found result.
- **Delete** removes the document. Confirm that it is no longer needed and that other documents do not depend on it. Do not assume that deleted content can be recovered from the normal history panel.
- **Discard changes** removes draft changes. On a previously published document, the published version remains. On a new document with no published version, discarding its draft can remove the new item entirely.

Find these actions in the document action menu if your role permits them. Read the confirmation dialog before continuing. If Studio reports incoming references, review the documents that link to this item and update their references first.

Removing the latest post can change what appears on the homepage. Keep at least one suitable published post available: the current homepage expects latest-post content.

## Check the result

After unpublishing, check `/posts` and any known links. After editing, verify both the short overview and the full story. If a removed post remains visible, follow [changes not appearing](troubleshooting.md#my-changes-are-not-on-the-website).
